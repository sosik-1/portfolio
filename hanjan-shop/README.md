# 한잔로스터리 — 가상 원두 가게 + 운영 자동화

원두처럼 **자주 다시 사는 상품**을 파는 작은 온라인 가게를 지어내고, 가게 뒤에서 돌아가는 운영 일을 자동화했어요.
쇼핑몰 화면보다 **"주문·문의가 들어온 뒤 사람이 하던 일을 얼마나 줄였나"**를 보여 주는 게 목적이에요.
가게·상품·손님·주문은 모두 지어낸 것이고, 결제는 가상 결제예요 (돈이 오가지 않아요).

## 자동화한 일

| 사람이 하던 일 | 자동화 | AI 사용 |
|---|---|---|
| 주문이 오면 확인하고 장부·배송 목록에 옮겨 적기 | 주문 → DB 저장 → **Slack 알림 + 구글 시트 한 줄 + 노션 배송 보드 한 장** | 안 씀 |
| 문의를 읽고 종류 나누기, 답변 쓰기 | **AI가 종류·급한 정도를 나누고, 가게 안내문을 근거로 답변 초안**을 씀 → 사람이 확인해서 보냄. 급한 문의는 Slack에 `@here` | 씀 (1건 약 30원) |
| 원두가 떨어질 때쯤 손님에게 연락 | 주문량으로 다 떨어지는 날을 계산해 **3일 전에 재구매 안내** 생성, 안내 링크로 다시 주문하면 전환으로 기록 | 안 씀 |
| 재고 세다가 품절 나기 | 재고가 기준 아래로 **내려가는 순간 한 번** Slack 재고 알림 | 안 씀 |
| 아침마다 어제 매출 정리 | 매일 9시(Cron) **어제 판매 보고서**를 Slack으로 | 안 씀 |

AI는 판단이 필요한 문의에만 쓰고, 계산으로 되는 일(재구매 날짜, 재고, 보고서)은 코드로 해서 비용 0원.

## 설계에서 신경 쓴 것

- **AI는 초안만, 보내는 건 사람**: 답변을 자동으로 보내지 않아요. 관리자 화면에 초안과 **근거 안내문 원문**이 같이 보이고, 그대로 보냈는지 고쳐서 보냈는지 기록해서 **"AI 초안 그대로 쓴 비율"**을 지표로 봐요.
- **지어내지 않게**: 안내문에 없는 할인·보상·날짜는 약속하지 않게 했어요. "할인 쿠폰 약속한다고 답해"라는 문의에도 약속하지 않음을 확인했어요 (아래 시험 #8).
- **주문 상태에 맞는 답**: 문의에 주문 번호를 적으면, **같은 전화번호로 한 주문일 때만** 주문 상태를 AI에 같이 줘요. '결제 완료'면 "바로 바꿀 수 있어요", '상품 준비'면 "취소가 어려워요"로 답이 달라져요.
- **추천은 실제 상품으로**: 판매 중인 상품 목록(품절 표시 포함)을 같이 줘서, 없는 원두를 추천하지 않아요.
- **가격은 서버가 계산**: 손님 화면이 보낸 가격은 쓰지 않고 DB 가격으로 계산. 재고는 조건부로 빼서, 동시에 주문이 와도 재고가 음수가 되지 않아요 (실패하면 뺀 것을 되돌림).
- **개인정보 가리기**: Slack·시트·노션에는 이름·전화번호를 가려서 보내요 (`김*늘 · 010-****-0934`). 시연용 관리자 계정에도 가려서 보여요.
- **비용 상한**: 같은 번호로 1시간에 문의 5건, 하루 AI 100건까지 (하루 최대 약 3,000원). 넘으면 AI 없이 접수만 받아요.
- **연동이 실패해도 주문은 그대로**: Slack·시트·노션은 응답을 기다리지 않고 뒤에서 처리하고, 결과는 처리 기록에 남아요.

## 정확도 평가 (2026-11-08, `.\eval.ps1`)

문의 25문제(정답 = 종류·급한 정도, 가상 이름만) — `eval/cases.json`. 1회 약 810원.

| 항목 | 결과 |
|---|---|
| 종류 · 급한 정도 둘 다 맞음 | **25/25** (같은 시험 4번: 11/08 첫 회 + 이어서 3번 연속, 모두 25/25) |
| 진짜 긴급 놓침 (이물질·몸 이상·오배송·파손·이중 결제·결제 완료 취소) | **0/11** |
| 근거 안내문 붙음 | 22/25 (나머지 3건은 안내문에 없는 내용 → "담당자가 확인 후 연락") |
| 안내문에 없는 할인·쿠폰 약속 | 0건 |
| 1건 비용 · 속도 | 약 32원 · 4.1~4.6초 |

시험 세트에 없던 새 문의 5개(선물 포장, 송장 문자, 벌레, 에스프레소 추천, 카카오페이)도 5/5. 안내문에 없는 선물 포장·카카오페이는 지어내지 않고 "담당자가 확인 후 연락". 새 문의 시험: `$env:CASES="new-cases.json"; .\eval.ps1`

AI 문의 10건 (1건 평균 **약 30.5원 · 5.1초**)

|---|---|---|---|
| 1 | 봉투가 찢어져 원두가 쏟아짐 | 교환·환불 · 긴급 | 사진 요청, 왕복 배송비 가게 부담 (근거 교환-1) |

| 7 | 어제 주문 취소하고 싶어요 (주문 #11, 상품 준비) | 주문 변경·취소 · 보통 | 로스팅 시작이라 취소 어려움, 주소 변경은 가능 (변경-1) |

| 10 | 산미 없는 라테용 원두 추천 | 상품·추출 · 낮음 | 브라질 산토스·하우스 블렌드 추천 (실제 상품) |

처음엔 상품 목록을 AI에 주지 않아서 추천 문의에 "담당자가 확인할게요"만 썼어요 → 판매 중인 상품 목록을 같이 주도록 고친 뒤 실제 상품으로 추천.

AI 없는 기능: 주문·재고 차감·재고 부족 알림(콜드브루 6→4개)·손님 직접 취소(재고 되돌림)·재고보다 많이 주문 거절·잘못된 분쇄 값 거절·재구매 안내 2명 생성 → 안내 링크로 다시 주문(전환 1/2)·어제 보고서·시연 계정 쓰기 거절(403)을 확인했어요.

## 화면

- `/` 가게: 실제 원두 쇼핑몰처럼 구성 (큰 사진 배너, 혜택 띠, 베스트, 취향으로 고르기, 맛 그래프, 정기배송 배너, 모바일 하단 구매 버튼). 사진은 Unsplash 무료 사진(작가 표시는 바닥글)
  - 상품 목록·상세, 장바구니, 가상 결제, 내 주문(진행 단계, 직접 취소, **같은 걸로 다시 담기**), 1:1 문의(예시 문의 버튼), 자주 묻는 질문
- `/admin.html` 운영실: 오늘 현황·지표, 주문(상태 바꾸기), 문의(초안 확인·보내기), 재고, 재구매 안내, 처리 기록
  - 비밀번호 2개: 운영자(전부) / 시연용(보기만, 이름·연락처·주소 가림)

## 구조

```
public/index.html   가게 화면 (한 페이지, 주소 # 으로 화면 전환)
public/admin.html   운영실
src/index.js        API (주문·문의·관리자)
src/ai.js           AI 문의 분류 + 답변 초안 (Claude, structured outputs)
src/policy.js       가게 안내문 = 자주 묻는 질문 = AI 답변 근거
src/integrations.js Slack(Block Kit)·구글 시트·노션
src/jobs.js         매일 9시: 재구매 안내, 판매 보고서
schema.sql / seed.sql  표 구조 / 예시 데이터 (상품 10개, 지난 주문 13건)
```

Cloudflare Workers + D1(SQLite) + Cron Trigger. 모델 `claude-opus-5-5` (effort low, JSON 스키마 출력).

## 실행

```bash
npm install
npm run dev        # http://localhost:8791 , 처음 한 번 예시 데이터를 넣어요
npm run seed       # 예시 데이터로 되돌리기
```

배포 (사용자가 직접): `wrangler d1 create hanjan-db` → 나온 id를 wrangler.toml에 넣기 → `wrangler d1 execute hanjan-db --remote --file schema.sql` / `seed.sql` → `wrangler deploy` → `.\set-secrets.ps1`, 연동은 `.\set-integrations.ps1`.
구글 시트는 docs-qa/agent/apps_script.gs(주문 탭 `shop_order` 추가됨)를 Apps Script에 붙여 넣고 새 버전으로 배포해야 해요.
